# Keyword Enhancement Pass — English (en) Content

Date: 2026-08-14

## Goal

Weave the site's best-performing English SEO keyword phrases (from
`keyword-list/en.json`) into the English content DB — titles, meta
descriptions, OG/JSON-LD fields, and other copy — without keyword stuffing,
and without inventing facts, changing dot counts/ages, or altering JSON
structure.

## Keyword source

`Ui-app-DB-json/keyword-list/en.json`, specifically:

- `data.native_phrases`, `data.pooled_from_other_locales` — the full phrase bank.
- `opportunity_summary` — the highest-value phrases, prioritized wherever a
  field's context allowed a natural fit:
  - `primary_term` / `recommended_local_phrase`: "Connect the dots worksheets for kids"
  - `print_modifier` / `free_modifier`: "Free dot to dot printables PDF"
  - `children_modifier`: "Connect the dots worksheets for kids"
  - `adult_modifier`: "Extreme dot to dot printables for adults"

## Scope

Full sweep of `Ui-app-DB-json/content/en/*.json`:

- `home.json`
- `about.json`, `contact.json` (blog.json and legal pages — privacy/terms —
  were reviewed and correctly left untouched: blog posts already had good
  keyword coverage, and legal boilerplate has no natural slot for SEO copy)
- `puzzles-canada.json`, `puzzles-uae.json`
- `puzzles-cute.json`
- `puzzles-dinosaurs.json`, `puzzles-circus.json`, `puzzles-space.json`
- `puzzles-flowers.json` (largest file, ~4,300 lines / 20 puzzles)
- `puzzles-garden.json`, `puzzles-ocean.json`, `puzzles-playgrounds.json`
- `puzzles-usa-250.json`

Fields touched (only where genuine copy, never placeholders/code notes):
`header.title`, `header.meta_description`, `header.og.title`,
`header.og.description`, `header.json_ld.description`/`name`, `body.h1`,
`body.description`/`tagline`, and equivalent per-puzzle fields.

## Round 1 — initial keyword insertion

Work was split across 8 parallel background agents by file group (home;
canada+uae; cute; dinosaurs+circus+space; flowers; garden+ocean+playgrounds;
usa-250; about+blog+contact), each instructed to:

- Use **at most one** well-fitting keyword phrase per field.
- Skip fields where nothing fit naturally rather than force it.
- Preserve facts, dot counts, ages, and all `{placeholder}` tokens exactly.

Result: **256 fields** updated across all files (224 per-puzzle/page fields
+ 32 collection-header fields), all validated as well-formed JSON.

## Round 2 — quality audit (anti-stuffing pass)

A second batch of 8 background agents re-reviewed every round-1 diff against
the keyword list, specifically judging for:

- **Keyword stuffing** — more than one phrase per field, repeated roots,
  awkward bolted-on phrasing.
- **Missed value** — fields left with no phrase, or a low-value phrase where
  a much stronger `opportunity_summary` phrase would have fit as naturally.

Findings:

| File(s) | Result |
|---|---|
| home / about / contact | 1 field smoothed (mild redundancy); rest clean |
| Cute | 2 fields fixed (stacked format-words, e.g. "worksheet, PDF") |
| Dinosaurs / Circus / Space | 0 issues — already used top-tier phrases correctly |
| Flowers | 0 issues — 21/21 fields already optimal |
| Canada / UAE | 8 fields fixed — broken comma-splice grammar from round 1, **including 2 cases where a fact had been accidentally dropped** (an age range on the falcon/dallah, and the word "striped" on the raccoon) — both restored |
| Garden / Ocean / Playgrounds | 1 fix per file (actual duplicate "dot to dot" stuffing in each collection meta_description) + 8 previously-untouched puzzle entries upgraded (seahorse, whale, playhouse-slide, carousel-horse, dashing-car, swing, slide, seesaw, monkey-bar) |
| USA-250 | 2 fields improved (tagline upgraded to the exact top-tier phrase; one awkward double-appositive sentence smoothed) |

Round 2 total: **49 additional field fixes**. A follow-up dry-run confirmed
zero remaining stuffing or grammar issues across all files.

## Database sync

Discovered mid-task: the site's static build does **not** read
`Ui-app-DB-json/content/en/*.json` directly — it reads
`mapping-check/export/en/*.json`, which is itself generated by
`export_locale_content.py` from the real source of truth,
`mapping-check/mapping_audit_*.db` (SQLite, table `mapping_audit`, columns
`puzzle_slug` / `language` / `new_key` / `new_value` / ...). The
`content/en/*.json` files edited above are a **bundled fallback copy only**.

Per explicit instruction, all edits were also written directly into the real
database:

- **Round 1**: 224 existing DB rows updated (matched by `puzzle_slug` +
  `new_key` + `language='en'`, diffed against the pre-session `git HEAD`
  version of each file so only genuine keyword edits were pushed — not any
  pre-existing drift between the DB export and the content files) + 32 new
  rows **inserted** for collection-level fields that had no DB row at all
  (every category except Canada lacks a `<category>-collection` slug in its
  DB — those collection headers exist only in the bundled `content/en` copy).
- **Round 2**: 49 further rows updated, diffed against a pre-round-2
  snapshot of `content/en` so only the audit's fixes were pushed.
- Verified after each round with a dry-run pass showing 0 remaining diffs
  ("already-matches") between `content/en` and the database.

`mapping-check/export/en/*.json` (the build-time export) was **intentionally
not regenerated** — per instruction, the DB and `content/en` are in sync,
but the export snapshot remains stale until `export_locale_content.py` is
run deliberately.

## Not done / explicitly out of scope

- Other locales (ar, de, fr, ja, ...) were not touched — this pass was
  English-only, per the request.
- `mapping-check/export/en/*.json` was not regenerated.
- `ui-app` was never touched (standing project rule).
